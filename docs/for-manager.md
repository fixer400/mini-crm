# Как устроена система (для руководителя)

**Что это.** Веб-приложение, где руководитель ставит задачи по стройкам, а исполнители их выполняют. Есть две роли: **постановщик** создаёт объекты и задачи, назначает исполнителя и принимает работу. **Исполнитель** берёт задачу в работу и сдаёт её на проверку. У задачи пять статусов: Новая → В работе → На проверке → Принята. С проверки задачу можно вернуть «На доработку», и тогда обязательно нужно написать, что исправить. Каждая смена статуса записывается в историю: кто, когда, из какого статуса в какой и с каким комментарием.

**Где хранятся данные.** В облачной базе данных Supabase. Приложение в браузере — это «окно» в базу. Важно: **правила доступа записаны в самой базе, а не в окне.** Даже если кто-то обойдёт интерфейс и отправит запрос напрямую (это может сделать любой, кто немного разбирается в программировании), база проверит, кто он, и откажет.

**Как защищены данные.**
- Войти можно только по email и паролю, которые выдал администратор. Зарегистрироваться самому нельзя.
- Роль (постановщик или исполнитель) назначает администратор. Сам пользователь сменить себе роль не может.
- Для каждой таблицы база знает, какие строки показывать конкретному человеку. Исполнитель получает только свои задачи и объекты, где у него есть задачи. Чужие задачи для него не существуют.
- Статус меняется только через одну «дверь». Она проверяет, разрешён ли такой шаг этому человеку. Поменять статус в обход, например сразу на «Принята», база не даст.
- Историю никто не может дописать, исправить или удалить, даже постановщик. Записи в неё добавляет только сама база при смене статуса.
- Секретный «ключ администратора» базы не попадает ни в приложение, ни в код на GitHub.

**Чего исполнитель сделать не может**, даже в обход интерфейса:
- увидеть чужие задачи, их историю и объекты, где у него нет задач;
- создать, отредактировать или удалить задачу или объект;
- сам принять свою задачу, перескочить через статус или тронуть чужую задачу;
- переназначить задачу на другого человека или сделать себя постановщиком;
- подделать или стереть историю.

Всё это проверено автоматическими тестами: они пытаются сделать перечисленное и убеждаются, что база отказывает.
